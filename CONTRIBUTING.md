# Contributing Guide

Thanks for contributing. Please read this guide before opening an issue or pull request.

## Getting Started

1. Search existing issues and pull requests to avoid duplicates.
2. For large changes, open an issue first to discuss the approach.
3. Fork the repository and create a dedicated working branch.

## Development Flow

1. Create a branch from `main` (or the default branch).
2. Make focused, atomic commits.
3. Run required tests and lint checks.
4. Fill in the pull request template clearly.

## Branch Naming Examples

- `feat/<short-description>`
- `fix/<short-description>`
- `docs/<short-description>`
- `chore/<short-description>`

## Commit Message Examples

- `feat: add issue triage workflow`
- `fix: correct typo in security policy`
- `docs: update contributing guide`

## Pull Request Requirements

- Clearly describe the purpose and context.
- Keep changes small enough for effective review.
- Include testing results or verification steps.
- Explicitly call out any breaking changes.

## When Opening an Issue

- Provide clear and reproducible steps.
- Separate expected behavior from actual behavior.
- Include logs, screenshots, and environment details when relevant.

## Code of Conduct

By participating in this project, you agree to follow `CODE_OF_CONDUCT.md`.
